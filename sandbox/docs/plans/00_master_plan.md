# 00 — Master Plan

The single source of truth for **how we run this implementation**. Read this before
starting any work. Details live in the other docs; this is the map.

---

## The one-line claim we are testing

> A **learned, state-dependent** weight `α` between the target-assignment objective and
> the collision-avoidance objective (produced by the Priority Arbitration Head) gives
> better multi-UAV coordination than a **fixed** `α`, in a 2D environment.

Everything in this project exists to make that comparison clean and defensible. If a
task does not help prove or disprove that claim, it is out of scope.

---

## Guiding principles

1. **Formulation before code.** The MDP, the reward terms, and the PAH training rule
   are written down and reviewed by the supervisor *before* we build them. See
   `docs/research/00_problem_formalization.md` and `01_pah_design.md`.
2. **Reproduce before innovate.** Stage 1 is reproducing the DA-MAPPO *mechanism* in
   our env. If we cannot reproduce a known result, our stack is broken and no new
   result from it is trustworthy.
3. **Environment correctness before RL.** The env gets unit tests and visual checks
   before any policy is trained on it. Most "RL won't learn" bugs are env bugs.
4. **One change at a time, always against a baseline.** Standard MAPPO → + assignment
   → + conflict graph → + PAH. Each step is a controlled experiment.
5. **Multi-seed or it didn't happen.** Every reported number is mean ± spread over
   ≥ 5 seeds. A single-seed result is a debugging aid, not a finding.
6. **Scope discipline.** 2D only. ≤ 8 drones. No features beyond the synopsis.
7. **Honest logging.** The `sessions/` log records what actually happened — failed
   runs, dead ends, and all. That record is what makes the thesis writing possible.

## Phases

| Phase | Name | Goal | Rough time | Milestone / "done when" |
|-------|------|------|-----------|--------------------------|
| **P0** | Formalization | Written, reviewed design of the MDP, reward, PAH, baselines | 2–3 weeks | Supervisor has signed off on `docs/research/00`–`03` and the open-questions list |
| **P1** | Environment | Custom 2D Gymnasium env, vectorized, tested | 3–5 weeks | All env unit tests pass; a scripted "go straight to target" agent behaves correctly; rendering works |
| **P2** | MAPPO core | Minimal clean MAPPO (actor + shared critic + GAE + PPO clip) | 3–4 weeks | MAPPO solves a 1-drone task and a standard Gym task; Standard-MAPPO baseline trains on Stage 1 env |
| **P3** | Assignment + conflict graph | Hungarian augmentation and conflict-graph neighbors integrated into obs | 3–4 weeks | DA-MAPPO-2D and IGAT-style baselines train; ablating assignment collapses success (matches DA-MAPPO Table VI) |
| **P4** | Priority Arbitration Head | PAH implemented and integrated; fixed-α baselines run | 4–6 weeks | Full model trains stably; learned `α` correlates sensibly with time-to-collision; fixed-α sweep complete |
| **P5** | Evaluation + ablation | Full experiment grid (swarm size × obstacle density), ablations, failure analysis | 6–8 weeks | Results tables + plots generated by script; the α-comparison verdict is in |
| **P6** | Writing | Thesis chapters | 4–6 weeks | Draft to supervisor |

Phases overlap (P1 and the small parts of P0/P3 run in parallel). The mapping to the
approved synopsis Gantt is in `01_roadmap.md`.

## What MUST happen

- [ ] P0 sign-off from the supervisor before serious coding
- [ ] Written OK from the supervisor on every deviation from the approved synopsis
      (PyBullet, action space, obstacle sensing — see `docs/research/04`)
- [ ] Every experiment: config file, fixed seeds, logged run, saved checkpoint
- [ ] ≥ 5 seeds per reported configuration
- [ ] The fixed-α baseline sweep (this is the comparison the whole thesis rests on)
- [ ] The assignment-ablation check against DA-MAPPO's reported collapse
- [ ] A `sessions/YYYY-MM-DD.md` at the end of every working session
- [ ] Env unit tests green before any training run

## What must NOT happen

- [ ] No PyBullet / 3D physics
- [ ] No training run without a config file and a seed
- [ ] No reported result from a single seed
- [ ] No change to the PAH core idea without asking Ayesha and Manish
- [ ] No silent deviation from the approved synopsis
- [ ] No `git commit` / `git push` unless Manish asks
- [ ] No fabricated numbers, plots, or "expected" results
- [ ] No scope creep (3D, > 8 drones, extra sensors, communication modelling)
