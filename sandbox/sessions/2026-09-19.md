## 5. Design decisions — Stage 3 plan

### Decision 1: Stage 2b common warm-start
**Kya:** teeno methods (B4, H, M) Stage 3 ke liye Stage 2b final checkpoint
se warm-start karenge.
**Kyun:** clean, apples-to-apples comparison. Har method ka apna Stage 2 final

**Ayesha ne approve kiya:** haan.

### Decision 2: Critic Freeze-First initialization
**Problem:** Stage 3 mein 8 drones honge (Stage 2 mein 5 the). Critic ka input
size `n_drones × obs_dim` hota hai — 5→8 drones se size change hoti hai, Stage
2b critic directly load nahi hoga (architecture mismatch).

Actor aur PAH Stage 2b se seedha transfer ho sakte hain (per-drone obs_dim
same rehti hai). Critic fresh random init hoga.

**Fix — Freeze-First approach:**
```
Stage 3 start pe:
  Actor  ← Stage 2b se load
  PAH    ← Stage 2b se load (M ke liye)
  Critic ← fresh random init

  Pehle ~500 episodes:
    - Actor FROZEN (koi update nahi)
    - Critic sirf train hota hai Stage 3 rollouts pe
    → Critic Stage 3 ki value function seekh leta hai
    → Actor stable rehta hai, noise nahi deta

  Episode ~500 ke baad:
    - Actor unfreeze
    - Normal training (actor + critic dono)
```

**Kyun yeh kaam karega:** yahi root cause tha jo aaj raat two-head critic mein
fail hua — fresh critic + converged actor ne noisy GAE advantages banaye jis se
entropy crash hua. Freeze-first mein critic ko "catch up" ka waqt milta hai
actor se pehle.

**500 episodes ka freeze duration:** Manish ko seed 42 pe test karke confirm
karna hoga — sahi number experiment se decide hoga. PyTorch mein `requires_grad`
toggle karne ka kaam hai.
