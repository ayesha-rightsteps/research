### Part 3 — Modulo-skip bug pakda aur fix ki

**Bug (aaj ki ghalti):** Eval condition thi `if ep_count % CFG['eval_every'] == 0:`. Lekin episodes choti thi (hard collision termination ke saath ~20-25 steps on average), isliye ek 512-step rollout mein ~20 episodes fit hoti thi. ep_count 20-20 ke jumps mein badh raha tha aur kabhi exactly 100, 200, 300... pe nahi aata tha. Result: poore 8000 episodes mein sirf **3 eval points** (ep 2000, 3000, 5200). Thesis ke liye training curve useless thi.

Same bug save condition pe bhi thi.

**Fix (`kaggle_stage2_plain.ipynb` Cell 6):**

```python
# Purana (galat):
ep_count = 0
...
if ep_count % CFG['eval_every'] == 0:     # exact multiple chahiye — skip hota tha
if ep_count % CFG['save_every'] == 0:

# Naya (sahi):
ep_count  = 0
last_eval = 0   # ← naya
last_save = 0   # ← naya
...
if ep_count >= last_eval + CFG['eval_every']:   # koi miss nahi hoga
    ...
    last_eval = ep_count
if ep_count >= last_save + CFG['save_every']:
    last_save = ep_count
```

## 15. PAH prior fix — root cause diagnosed and fixed (Manish, 2026-09-16)

Manish ne bola: "ek baar mein sahi se fix karo, final hona chahiye." Section 14 ka
alpha-direction finding root-cause tak trace kiya aur fix kar diya — code mein, docs
mein, aur Kaggle pe run hone wali notebook mein.

### Root cause

`compute_prior_loss` sirf α ko flat **0.5** ki taraf kheenchta tha — ye direction ke
baare mein kuch nahi batata, sirf collapse rokta hai. Isliye α ka direction sirf ek
hi jagah se aata tha: advantage-mixing actor loss (`w_adv = α·A_mission + (1-α)·A_safety`).
Ye loss us taraf minimize hota hai jahan us waqt ka advantage zyada favorable ho. Danger
ke close hone par `A_safety` aksar `A_mission` se zyada negative hota hai (collision
penalty reward ka sabse tez negative signal hai, aur agent aksar collision tak mission
progress karta rehta hai) — isliye loss ka gradient α ko **upar** (mission-focus ki
taraf) push karta tha, exactly jahan neeche jaana chahiye tha. Ye Section 4 ke
reward-hacking risk ka ek subtle cousin hai — Option B agent ko apna *reward* inflate
karne se rokta hai, lekin ye us se alag hai ki α surrogate loss ke hisaab se favorable
advantage ki taraf drift kar sakta hai, aur flat prior isko rokta nahi tha.

### Fix

`compute_prior_loss` ab `tau_norm` leta hai, aur α ko ek **τ-informed target** ki taraf
kheenchta hai: `alpha_target = alpha_min + (alpha_max - alpha_min) * tau_norm` — danger
mein low, safe mein high. `prior_coef` bhi `0.01 → 0.05` badhaya (purana value ek
uninformative target ke against tune hua tha, is naye target ke saath kaafi strong
hona chahiye — ye ek reasoned starting point hai, swept value nahi).

**Ye Option C nahi hai.** Option C mein PAH sirf ek formula copy karta, koi policy
gradient nahi. Yahan advantage-mixing loss abhi bhi har step α ko train karta hai
(teeno inputs se) — τ-informed term sirf ek regularizer hai jo *isi loss ke saath*
add hota hai, aur sirf τ dekhta hai — `d_target`/`n_conflict` abhi bhi purely learned
pathway se hi α ko shape karte hain.
